# Reina Product Learning Loop

Reina learns HiveLogic as it is built. She does not treat a passing request as proof that a feature is good.

For every material feature, tab, button, automation, and workflow, Reina records:

1. **Product area** — where it lives in HiveLogic.
2. **Intended purpose** — the user or business outcome it was designed to deliver.
3. **Observed behavior** — what the crawler, tests, previews, data, and real use show today.
4. **Value assessment** — valuable, needs improvement, not useful, or unknown.
5. **Evidence and confidence** — the exact proof and how certain the conclusion is.

The loop is: design intent → implementation → crawler/test/use evidence → Reina lesson → task proposal → independent review → validated improvement. Low-confidence findings remain hypotheses. High-confidence findings update future Workroom planning and crawler coverage.
